# Exam-Prep V4 — decommission audit and test removal

تاریخ: ۲۰۲۶-۰۸-۱۹ · دامنه: `apps/classes` (V4 source-aware split pipeline) · وضعیت: **تست‌ها حذف شد، سورس دست‌نخورده ماند**

مالک دستور داد تست‌های V4 حذف شوند، با این توضیح که «خودش حذف شده و استفاده نمی‌شود».
پیش از حذف، ممیزی شد تا مطمئن شویم چیزی که پاک می‌کنیم واقعاً مرده است — چون
`CLAUDE.md` هشدار می‌دهد بعضی ماژول‌های `_v4` هنوز در مسیر تولید Mistral زنده‌اند.
نتیجه‌ی ممیزی این مقدمه را **نیمه‌درست** نشان داد و همان چیزی است که این سند ثبت می‌کند.

**خلاصه:** V4 یک زیرسیستم **نیمه‌سیم‌کشی‌شده** است — ORM و سیگنال‌ها و ذخیره‌سازی‌اش زنده‌اند،
اما هیچ مسیر HTTP ندارد، پس نه کاربر می‌تواند صدایش بزند و نه UI فرانتش کار می‌کند.
حذف‌نشده است؛ **غیرقابل‌دسترس** است.

## ۲. چه چیزی حذف شد

۳۶ فایل با الگوی `backend/apps/classes/test_exam_prep_v4_*.py` (۲۱۹ تست).

**عمداً حذف نشد:** `test_exam_prep_mistral_page_batch_transcriber_v4.py`.
نامش به `_v4` ختم می‌شود ولی تستِ **Mistral** است، نه تستِ پایپ‌لاین V4 — الگوی گشاد `*v4*`
آن را هم می‌گرفت. الگوی دقیق `test_exam_prep_v4_*` آن را کنار می‌گذارد.

**دست‌نخورده ماند (و باید بماند):** شش تستِ غیر-V4 که به V4 اشاره می‌کنند —
`test_exam_prep_mistral_production_boundary.py` و `test_exam_prep_mistral_visual_boundary.py` و
`test_exam_prep_mistral_visual_runtime_hardening.py` **نگهبان** هستند
(`assert "exam_prep_v4" not in source`) و دقیقاً همان چیزی را حفظ می‌کنند که مسیر تولید را
تمیز نگه می‌دارد؛ `test_exam_prep_legacy_audit.py` و `test_exam_prep_simple_pipeline.py`
از مدل‌های V4 دیتا می‌سازند؛ `test_prompts_contract.py` کلیدهای پرامپت V4 را قفل می‌کند.

پیش از حذف تأیید شد **هیچ فایلی از ماژول‌های تستِ V4 import نمی‌کند** (فیکسچر مشترکی گم نمی‌شود).

## ۴. رفع جانبی — سقف ۲۶۰ کاراکتری مسیر در ویندوز

`test_exam_prep_mistral_diagnostic_replay_store.py` تستِ V4 **نیست** و پس از حذف تنها سرخِ
باقی‌مانده بود. `_DiagnosticStore` (در `replay_exam_prep_mistral_visual_stage3.py`) نامِ آبجکت را
به ~۷۸ کاراکتر فشرده می‌کند، ولی دایرکتوری `--out` که کاربر می‌دهد بیرون از کنترل اوست و
خودش می‌تواند به‌قدری عمیق باشد که هر فرزندی سرریز کند. `_long_path_root()` اضافه شد: روی
ویندوز ریشه را با پیشوند `\\?\` می‌سازد (از MAX_PATH خارج می‌شود)، جای دیگر بی‌اثر است.
پیشوند کاملاً داخلی می‌ماند — `self.root` فقط برای join و مبنای `relative_to` استفاده می‌شود و
هرگز چاپ نمی‌شود. تست هم از `store.root` می‌خواند نه از ریشه‌ی خام، وگرنه خودِ تست به همان
سقف می‌خورد.

## ۵. توصیه برای گام بعد (انجام نشد — دامنه‌ی مالک)

حذف کامل V4 عمداً انجام **نشد**، چون به مایگریشن‌های drop روی ۸ گروه جدول، ویرایش
`apps.py` و `signals.py` (فایل‌های زنده‌ی مشترک با مسیر تولید)، حذف مسیر مدیا و پاک‌سازی
UI فرانت نیاز دارد — شعاع انفجاری بزرگ‌تر از «تست‌ها را حذف کن». اگر مالک تصمیم به
بازنشستگی کامل گرفت، ترتیب کم‌ریسک این است:

1. UI و سرویس‌های فرانت V4 (چون همین حالا ۴۰۴ می‌گیرند — صفر ریسک رگرسیون).
2. `signals.py` و `apps.py` را از V4 جدا کن؛ سه تست مرزی باید سبز بمانند.
3. سرویس‌ها/ویوها/تسک‌ها/سریالایزرها + `urls_v4.py` + کامند بازیابی.
4. کلیدهای پرامپت `exam_prep_v4_*` و همگام‌سازی `test_prompts_contract.py`.
5. **آخر از همه** مایگریشن‌های drop برای `0040`–`0047` — با بکاپ، چون داده‌ی واقعی
   ممکن است در آن جداول باشد.

قبل از قدم ۵ باید روی پروداکشن شمرده شود که این جداول خالی‌اند یا نه.
